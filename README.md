# 听写小助手 V0.3.8｜iPhone MP3 兼容性修复版

## 本次重点

- **修复 iPhone 上 MP3 试听提示“被浏览器阻止”以及正式听写停留在“准备开始”**。
- 从 HTML `audio.play()` 改为 **Web Audio**：在用户点击“开始”或“试听”时立即解锁音频引擎，MP3 在后台预加载并解码，完整播放后才朗读提示语。
- 使用你上传的 `Dir_OP.mp3` 和 `Dir_EP.mp3`，保留音频内容，但移除附带的封面图和多余元数据、重新封装为标准立体声 MP3。
- 开场 `Dir_OP.mp3`（约 7.2 秒）→ “准备好了吗？现在开始听写。” → 自动听写；结束 `Dir_EP.mp3`（约 8.7 秒）→ “本次听写已完成。辛苦了！”。
- 若无法解码或被系统中断，会显示错误并自动跳过音乐继续播报，不能再永久卡在“准备开始”。
- 独立手动录入、词库、组合、中文标记拼音、自动播报、重复次数、书写时间、可选中文/英文系统声音均保留。

## 如何升级

1. 在原听写工具的“设置”中先 **导出 JSON 词库备份**。
2. 下载 `听写小助手_iPhone音乐播放修复_V0.3.8.zip`，解压并上传 **解压后的文件和完整 assets 目录** 到原听写工具的 GitHub Pages 仓库根目录（不是宝可梦图鉴仓库）。不要直接上传 ZIP。
3. 确认 `assets/audio/Dir_OP.mp3`、`assets/audio/Dir_EP.mp3` 和新文件 `music-engine.js` 都上传成功。
4. GitHub Pages 部署完成后在 iPhone 重新打开，确认顶部版本显示 `v0.3.8`。建议使用工具里的“设置 → 检查更新”或用 Safari 重新打开原网址刷新。**不要删除主屏幕应用，也不要清空 Safari 网站数据**。

## iPhone 验收

1. 进入“听写”，等待音乐区域显示“已解码可播放（7.2秒 / 8.7秒）”，分别点击 OP/EP 试听。
2. 保持手机**非静音**，媒体音量调到 50% 以上；在 Safari 前台测试，不要锁屏。
3. 选择含 2～3 个词语的词库，点击“开始播报”。预期：开始音乐→开始提示语→词语→结束音乐→完成提示语。
4. 若曾经在旧版选择过本机 MP3，先点对应的“移除本机音乐”，确保使用新版内置的经过兼容性处理的音乐。
5. 若仍失败，请截取音乐区域的状态行（如“解码失败”或“已解码可播放”）以及错误提示，不需要透露私人数据。

## 中文音色的真实限制

截图里 Safari 只报告 4 项中文声音，其中若干名称重复。这不是网页里漏了音色，而是手机浏览器实际提供的声音列表；网页无法直接添加新的系统发音人。更改 iPhone 设置中的可用语音可能影响系统，但 **不保证** Safari 会增加条目。如果希望使用更多真正不同的中文发音人，需要额外的 TTS 语音服务（目前不启用）。

## 测试说明

已检查 MP3 为有效音频，并通过 Node 业务逻辑测试；正式 iPhone Safari 播放仍需要你实机验证，不能以电脑端测试代替。

## 数据安全

所有词库和听写设置仍保存在原本的本地浏览器存储中，本次不做数据迁移或删除。音乐文件作为公开 GitHub Pages 项目静态资源发布；请确保你拥有把音乐文件公开提供的权利。
